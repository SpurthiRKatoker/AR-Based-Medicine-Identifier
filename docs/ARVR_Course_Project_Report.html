1. Executive Summary & Problem Formulation

Pharmaceutical identification poses severe challenges for elderly patients, low-vision individuals, and individuals experiencing motor tremors. Traditional mobile applications rely on flat, multi-screen navigation flows that disorient users and force cognitive context switching away from physical medicine packages.

This project implements an offline-first Augmented Reality (AR) spatial computing system that anchors real-time pharmaceutical intelligence directly over physical medicine packaging. By marrying low-level 6-DoF SLAM/VIO, custom OpenGL ES 2.0 hardware texture pass-through, spatial tremor filtering, and multimodal auditory augmentation, the system provides instantaneous identification without leaving the live camera view.

3. 6-DoF SLAM & Visual-Inertial Odometry (VIO)

The core spatial tracking subsystem is implemented in ArSessionManager.kt using Google ARCore. It establishes a real-time world coordinate reference frame using Visual-Inertial Odometry.

Key VIO Capabilities:

  • 6 Degrees of Freedom Pose Estimation: Tracks both 3-axis translation (x, y, z) and 3-axis rotational orientation via unit quaternions (qx, qy, qz, qw) at 60 frames per second.
  • Plane Finding (Horizontal & Vertical): Identifies pharmacy counters, bedside tables, and vertical storage walls using Config.PlaneFindingMode.HORIZONTAL_AND_VERTICAL.
  • Continuous Macro Autofocus: Configures Config.FocusMode.AUTO to resolve micro-typography on pharmaceutical labels (down to 6pt fonts) at 10–30cm ranges without losing tracking features.

4. Low-Level OpenGL ES 2.0 Graphics Rendering & GLSL Shaders

To prevent the latency and jitter associated with standard Android UI canvas drawing, the application integrates a low-level graphics pipeline in ArCameraSurfaceView.kt.

4.1 External Hardware Texture Streaming

The renderer binds directly to Android's graphic buffer using GL_TEXTURE_EXTERNAL_OES. This enables Direct Memory Access (DMA) from the camera hardware sensor into GPU memory without CPU copying: 

val textures = IntArray(1)
GLES20.glGenTextures(1, textures, 0)
textureId = textures[0]
GLES20.glBindTexture(GLES11Ext.GL_TEXTURE_EXTERNAL_OES, textureId)
session.setCameraTextureName(textureId)

4.2 Custom GLSL Shaders

Vertex Shader:

attribute vec4 a_Position;
attribute vec2 a_TexCoord;
varying vec2 v_TexCoord;

void main() {
    gl_Position = a_Position;
    v_TexCoord = a_TexCoord;
}

Fragment Shader:

#extension GL_OES_EGL_image_external : require
precision mediump float;

varying vec2 v_TexCoord;
uniform samplerExternalOES u_Texture;

void main() {
    gl_FragColor = texture2D(u_Texture, v_TexCoord);
}

4.3 UV Coordinate Transformation & Aspect Ratio Compensation

Because smartphone camera sensors (typically 4:3) do not match device screens (19.5:9), raw textures would appear distorted. The pipeline performs on-the-fly coordinate transformation on every draw frame: 

frame.transformCoordinates2d(
    Coordinates2d.OPENGL_NORMALIZED_DEVICE_COORDINATES,
    QUAD_COORDS,
    Coordinates2d.TEXTURE_NORMALIZED,
    transformedTexCoords
)

This computes the sensor mount rotation, screen rotation, and aspect cropping, guaranteeing geometric fidelity.

5. Spatial Human-Computer Interaction (HCI) & Tremor Filter

Standard touch interfaces fail in handheld AR because moving the phone to point at packages causes accidental touch activations. In AccessibleTouchGestures.kt, the entire live camera viewport acts as a spatial gesture surface with Euclidean motion filtering:

Euclidean Drift Formulation:

distance = sqrt((x_current - x_down)² + (y_current - y_down)²)

If distance > 20px, the gesture is immediately aborted as involuntary tremor or intentional camera panning. Accidental triggers are suppressed, and an informative status pill is shown.

Spatial Gesture Actions

  • Single Tap: Captures frame, runs on-device OCR, matches medicine, speaks Basic Name and Dosage, and spawns the 3D AR card.
  • Double Tap (< 300ms): In-place speech playback of Warnings and Side Effects.
  • Long Press (≥ 500ms): In-place speech playback of the Full Clinical Monograph.

6. Instant 3D AR Medicine Card Overlay

Upon identification, the application spawns Live3DArMedicineCard directly on the camera viewport:

  • Glassmorphic Depth Aesthetic: Translucent midnight slate (#EE0B132B, 93% opacity) allows the user to see the physical package beneath the information card.
  • Chromatic Verification Borders: Emerald Green (#81C784) for verified matches, Amber (#FFB74D) for multi-strength ambiguity, Crimson (#E57373) for uncatalogued packages.
  • Dynamic Reticle Feedback: Search reticle transitions from searching blue to verified green upon package lock.
  • One-Touch Reset Control: "Scan Again" cleanly clears the overlay and returns the camera to scan state without screen transitions.
